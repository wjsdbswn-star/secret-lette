# 사라지는 글 v11 — 백업 복원 저항형 저장 구조

## 목적
관리자가 **만료 후 Cloudflare D1 Time Travel을 복원하더라도** 글 암호문을 재구성할 수 없게 설계합니다.

## 저장 위치
- 작성자 앱: AES-GCM-256 암호화, 복호화 키는 편지 링크의 `#k=` 부분에만 포함. 이 부분은 일반 HTTP 요청에 전송되지 않습니다.
- Cloudflare D1 `letters_v11`: 무작위 ID·열람 방식·유효기간·소멸 기준·열람 상태만 저장. 원문, IV, 암호문, 복호화 키 미저장.
- Cloudflare **비공개 R2 버킷** `PRIVATE_BLOBS`: 암호화된 글과 IV만 객체별 저장. 공개 도메인, 공개 버킷, 캐시 사용 금지.
- 최초 1회 보기: 원자적 승인 처리 후 R2 객체 삭제 **성공 후** 응답. 삭제 실패 시 재시도용 D1 tombstone 유지.
- 여러 명 보기: 공통 열람 종료시각을 지키며 만료 요청 시 즉시 R2 삭제. 자동 Cron 매분 만료 객체와 D1 메타데이터 삭제.
- R2 삭제 후 D1의 이전 상태만 복구하더라도 R2 원본이 없으므로 서버에서는 글을 다시 제공할 수 없음.

## 현 상태 (중요)
v11 서버 코드는 추가했지만 **R2 버킷 활성화·Worker 연결 전**입니다.
- `GET /v11/health`는 연결되기 전에는 503과 `ok:false`를 반환합니다.
- `POST /v11/create`, `POST /v11/open`도 연결되지 않으면 **503 실패**, 기존 v10 D1 암호문 저장으로 **자동 다운그레이드하지 않음**.
- 기존 v10 앱·편지 링크는 기능 유지. v11 보안 개선이 v10 과거 데이터나 백업을 소급 삭제하지는 않음.
- v11 편지 링크는 `/s/<24자 무작위 ID>#k=<클라이언트 키>`로 예정. `/l/` 기존 링크와 혼동 방지.

## 활성화에 필요한 승인 및 자원
1. 사용자가 Cloudflare 계정의 **R2 Object Storage 구독을 활성화**해야 합니다. 무료 사용량이 있지만 종량제 과금 가능하며 결제 절차가 있을 수 있습니다.
2. 새 **비공개** R2 버킷 `secret-letter-ephemeral-v11` 생성. 객체 공개 설정과 복제·백업 등 정책 확인.
3. `worker/wrangler.toml`에 다음 바인딩 추가 후 배포:

```toml
[[r2_buckets]]
binding = "PRIVATE_BLOBS"
bucket_name = "secret-letter-ephemeral-v11"
```

4. 배포 후 `GET /v11/health`의 `ok:true` 확인, 신규 v11 R2 실서버 송수신·삭제 테스트.
5. 신규 APK에서만 v11 API와 `/s/` 공유 링크 강제 사용하도록 빌드. v11 실패 시 사용자에게 오류를 보여 주고 구식 저장 방식으로 되돌아가지 않음.
6. 보조 안전장치로 **R2 객체 31일 경과 자동 만료 규칙** 적용 (30일간 미열람 상태로 둘 수 있는 구조). 주된 소멸은 Worker 분단위 삭제.
7. 장애 시 R2 삭제 작업이 지연될 수 있습니다. D1 열람 차단은 독립적으로 적용.

## 절대 보장할 수 없는 부분
- 만료 전에 수신자/관리자/제삼자가 따로 저장한 **암호문과 전체 편지 링크(키 포함)**의 조합.
- 화면 캡처, 사진, 복사, 녹화, 사람이 기억한 내용.
- 공급자의 내부 스냅샷·물리적 복제 데이터까지 즉시 삭제된다는 증명.
- 이미 과거 v10 D1에 저장해 놓은 암호문의 Time Travel 보존기한.
- 비밀 링크를 훔쳐 만료 전에 열람하는 경우. 링크 소유자 신원인증은 없음.

## 안전성 판단
- '관리자가 일반 D1 백업 복원을 해도 내용은 복원되지 않는다': **v11 구조상 기대 가능**.
- '만료 이전에 운영자가 의도적으로 복사한 내용까지 복구 불가능': **불가능**.
- '100% 완전 삭제': **약속 금지**.
- 외부 보안 검증과 Cloudflare 실제 R2 데이터 삭제 시험 전에는 보안 수준을 확정 표현하지 않음.
